# 参数包络分析（基于 IDA 反编译 0x140F98D00）

## 角色实体参考

`OnEnter` 的参数写入全部在**角色实体**上，位于 `rideOn + 0x98`（dec 152 = hex 0x98）。

参数写入模式：每个参数是 `flag byte + float value` 对，flag 在 value 前 0x10 字节。

## 关键判断

1. **+0x3950（rideKind 标量）**：这是唯一的"方向控制"参数。Front=0, Left=1, Right=2。但覆写 post-OnEnter 无效，因为动画图在 OnEnter 写入阶段已经读取了该值。

2. **+0x3740（设为 -1.0）** 和 **+0x3DD0（设为 1.0）**：这两个值在 OnEnter 前为 0，OnEnter 后变为非零。可能被动画图用作"启动上车动画"的触发器。

3. **+0x3770（派生值）**：来自 runtime+0x240，可能是秒表值。

## 参数包络恢复方案

在 OnEnter hook 中：
1. **调用前**：保存关键参数值（特别是 +0x3740, +0x3770, +0x3950, +0x3DD0 和所有 flag）
2. **调用原始 OnEnter**：获取参数设置和 entity attach 的副作用
3. **调用后**：恢复参数到之前的值
4. 继续现有的 ProcessVehicleAttach gate forcing + FastDrive 路径

预期效果：动画图收到的是"上车前"的参数包络，不会触发上车动画剪辑。
